# YouTube → Discord 自動投稿

ピックルボールワン公式YouTube（[@pickle-one](https://www.youtube.com/@pickle-one)）に
新しい動画が公開されたら、Discordの指定チャンネルに自動で投稿します。

- 監視対象チャンネルID: `UCoHy7BYunccawKcweDPdgtg`
- 実行基盤: GitHub Actions（15分おき・無料）
- 依存パッケージ: なし（Python標準ライブラリのみ）

---

## セットアップ手順

### 1. Discord側でWebhookを作る

投稿したいDiscordチャンネルで:

1. チャンネル名の横の **⚙️（チャンネルの編集）** をクリック
2. 左メニューの **連携サービス** → **ウェブフック** → **新しいウェブフック**
3. 名前とアイコンを設定（例: 「YouTube通知」）
4. **ウェブフックURLをコピー** をクリック

> ⚠️ このURLを知っている人は誰でもそのチャンネルに投稿できます。
> SlackやNotionなど、社内であっても公開の場に貼らないでください。

### 2. GitHubリポジトリを作る

このフォルダの中身をそのままリポジトリにpushします。

```bash
git init
git add .
git commit -m "YouTube→Discord 自動投稿を追加"
git branch -M main
git remote add origin https://github.com/<組織名>/<リポジトリ名>.git
git push -u origin main
```

### 3. Webhook URLをSecretsに登録する

GitHubのリポジトリページで:

**Settings** → **Secrets and variables** → **Actions** → **New repository secret**

| 項目 | 値 |
|---|---|
| Name | `DISCORD_WEBHOOK_URL` |
| Secret | 手順1でコピーしたURL |

### 4. ワークフローに書き込み権限を与える

**Settings** → **Actions** → **General** → 一番下の **Workflow permissions** で
**Read and write permissions** を選んで **Save**。

（通知済みの動画リスト `state.json` をリポジトリに書き戻すために必要です）

### 5. 動作確認

**Actions** タブ → 左の **YouTube → Discord** → **Run workflow**。

- **1回目の実行では何も投稿されません。** これは正常な動作です。
  既存の動画15本を「通知済み」として記録するだけで、これがないと
  設置した瞬間に過去の動画が一気にDiscordに流れ込んでしまいます。
- 2回目以降、**そこから先に公開された新しい動画だけ**が投稿されます。

投稿内容を事前に確認したい場合は、**Run workflow** の
`dry_run` にチェックを入れて実行してください。Discordには送らず、
送信予定の内容がログに表示されるだけになります。

## 投稿されるもの / されないもの

| 種類 | 既定の動作 |
|---|---|
| 通常の動画 | ✅ 投稿する |
| ショート（Shorts） | ✅ 投稿する |
| ライブ配信（配信中） | ❌ 投稿しない（配信終了後、アーカイブとして通常動画の扱いで投稿されます） |

Discordにはこの形で投稿されます。

通常の動画:

```
＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
🎥 新しい動画が公開されました‼️
＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
https://www.youtube.com/watch?v=xxxxxxxxxxx
```

ショート:

```
＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
⚡️ 新しいショートが公開されました‼️
＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
https://www.youtube.com/watch?v=xxxxxxxxxxx
```

URLの行は、実際のDiscord上ではサムネイル付きの再生カードとして展開されます。

### 投稿される量の目安

調査時点（2026-08-22〜09-03の13日間）の実績:

| | 本数 | ペース |
|---|---|---|
| Shorts | 13本 | 約1本/日 |
| 通常動画 | 2本 | 約1.1本/週 |
| **合計** | **15本** | **約1.2本/日** |

1日あたり1本強なので、チャンネルが埋まるような量ではありません。

**通常動画とShortsで投稿文を分けてあります。** 週1本しかない通常動画が、
毎日流れるShortsに埋もれて見落とされるのを防ぐためです。
種類の判定はもともと必要な処理なので、追加のコストはかかっていません。

### Shortsを止めたくなったら

`.github/workflows/youtube-to-discord.yml` の

```yaml
POST_SHORTS: "true"
```

を `"false"` に変えてcommitすれば、通常動画だけになります（週1本程度）。

### Shortsを別チャンネルに分けたい場合

1. Shorts用のDiscordチャンネルでWebhookを作る（手順1と同じ要領）
2. そのURLを `SHORTS_WEBHOOK_URL` という名前でSecretsに登録する
3. ワークフローの次の行のコメント（`#`）を外してcommitする

```yaml
# SHORTS_WEBHOOK_URL: ${{ secrets.SHORTS_WEBHOOK_URL }}
```

これで通常動画とShortsが別々のチャンネルに流れます。

## 投稿文をカスタマイズする

`.github/workflows/youtube-to-discord.yml` の次の2つを編集します。

| 設定 | 対象 |
|---|---|
| `MESSAGE_TEMPLATE` | 通常の動画 |
| `SHORTS_MESSAGE_TEMPLATE` | ショート |

使える変数は3つです。

| 変数 | 中身 |
|---|---|
| `{channel}` | チャンネル名（例: ピックルボールワン \| PICKLEBALL ONE） |
| `{title}` | 動画のタイトル |
| `{url}` | 動画のURL |

複数行の文面は `|-` を付けて、次の行から字下げして書きます（現在の設定もこの形です）。

```yaml
MESSAGE_TEMPLATE: |-
  ＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
  🎥 新しい動画が公開されました‼️
  ＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
  {url}
```

1行だけなら `"..."` で囲んで書けます。改行を入れたい位置には `\n` と書きます。

```yaml
SHORTS_MESSAGE_TEMPLATE: "⚡️ ショート更新！\n{url}"
```

> 区切り線（`＝`）の長さは本文の長さに合わせてあります。
> 通常の動画は16文字、ショートは18文字です。
> 文言を変えるときは、線の長さも一緒に調整すると見た目が揃います。

> URLを本文に入れておくと、Discordが自動でサムネイル付きの
> 再生カードを展開します。`{title}` を入れなくても動画名は表示されます。
>
> `@everyone` を実際に鳴らしたい場合は `notify.py` の
> `"allowed_mentions": {"parse": []}` を `{"parse": ["everyone"]}` に変更してください。
> 既定では誤爆防止のため、メンションは文字列として表示されるだけで通知は飛びません。
> なお毎日流れるショートで `@everyone` を鳴らすのは、メンバーが通知を切る原因に
> なりやすいので避けたほうが無難です。

## 実行間隔を変える

`.github/workflows/youtube-to-discord.yml` の `cron` を編集します。

```yaml
- cron: "*/15 * * * *"   # 15分おき
```

**プライベートリポジトリの場合は注意**: GitHub Actionsの無料枠は月2000分です。
15分おき（月約2900回）だと枠を超える可能性があります。次のどちらかにしてください。

- リポジトリを**パブリック**にする → 実行時間は無制限で無料
  （Webhook URLはSecretsに入っているのでコードを公開しても漏れません）
- `"*/30 * * * *"`（30分おき）や `"0 * * * *"`（1時間おき）に間隔を広げる

このチャンネルの投稿頻度は1日1本程度なので、30分おきでも実用上まったく問題ありません。

なお、GitHubの定時実行は**混雑時に数分〜十数分遅れる**ことがあります。
「ぴったり15分おき」ではなく「おおむね15分おき」と考えてください。

## つまずいたときは

**何も投稿されない**
- 1回目の実行では投稿されない仕様です。まず新しい動画が1本公開されるのを待ってください。
- すぐ試したい場合は `state.json` の中の `seen` から動画IDをいくつか削除してcommitすると、その動画が「新着」として再投稿されます。

**`state.json` の保存に失敗する**
- 手順4のワークフロー書き込み権限（Read and write permissions）が未設定です。

**Discordに届かない / HTTP 401・404 と出る**
- Webhookが削除されたか、Secretに登録したURLが間違っています。手順1からやり直してください。

**ログに「フィード取得に失敗 (試行 1/5)」と出る**
- 正常です。YouTubeのRSSは正常なチャンネルでも散発的に404を返すため、
  最大5回リトライする作りにしています。5回とも失敗した場合は何もせず終了し、
  取りこぼさないよう次回の実行で再試行します。

**しばらく経ったら動かなくなった**
- GitHubは60日間まったく更新のないリポジトリの定時実行を自動停止します。
  Actionsタブに再開ボタンが出るので押してください。
  （新着動画があるたびに `state.json` がcommitされるため、通常は停止しません）
